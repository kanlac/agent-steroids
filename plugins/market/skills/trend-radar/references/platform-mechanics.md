# 平台操作细节

## Reddit:公开 `.json` 端点,免费,但要克制

Reddit 几乎任何页面加 `.json` 后缀都会返回结构化数据,不需要认证:

- 发现(不需要关键词,直接看版块动态,这是最纯粹的自底向上方式):
  `https://www.reddit.com/r/<subreddit>/hot.json`、`/new.json`、`/top.json?t=month`
- 搜索(需要关键词):
  `https://www.reddit.com/search.json?q=<query>&sort=relevance&t=month`
- 帖子 + 评论树(带 `score` 字段,可以直接筛热门回复):
  `https://www.reddit.com/r/<sub>/comments/<id>/<slug>.json?sort=top`

这是未授权的公开访问,不是正式 API 权限。Reddit 2023 年那次 API 收费改革后对这类用法态度收紧了,请求快了容易被限流或按 User-Agent/IP 封掉。带一个正常浏览器风格的 User-Agent,控制请求间隔,不要短时间内对同一版块打几十次请求。

先确定几个跟目标领域相关的垂直版块,扫它们的 hot/new,而不是上来就用宽泛关键词 search——版块动态才是真正的"自底向上",search 本质还是要你先给一个假设词。

## X/Twitter:走浏览器 cookie,免费,但查询要短

如果环境里有 `last30days` 这个工具(`scripts/last30days.py`),它内置了免费的 X 搜索能力,走的是"拿你自己登录 x.com 的浏览器 cookie 去请求 X 内部的 GraphQL 接口",等价于免费版 API,不需要额外付费服务。配置方式:

```
FROM_BROWSER=auto
```

写进它的 `.env` 配置(具体路径看该工具自己的文档),前提是你在本机某个浏览器里登录过 x.com。如果自动扫描 cookie 因为系统权限(macOS Keychain/Full Disk Access)读不出来,退化方案是手动从浏览器开发者工具里复制 `auth_token`、`ct0` 两个 cookie 值,直接写进配置。

**踩过的坑**:X 的搜索对长句子/长查询很敏感,一整句英文描述式的查询经常直接返回 0 结果或解析报错;换成 2-4 个词的短查询(比如 `"AI image generator"` 而不是一整段话描述需求)命中率明显更高。查询效果不好时,先怀疑是不是查询太长,再怀疑是不是真没有相关内容。

X 搜索返回的是"当前时间点"的快照,不是历史趋势曲线——它能告诉你现在大家在聊什么,证明不了"这个话题是不是最近才冒出来的",后者需要配合搜索量类工具的历史数据。

## TikTok / Instagram:通常需要付费抓取服务

TikTok/Instagram 没有面向个人开发者的公开搜索 API,`last30days` 这类工具一般通过第三方抓取服务(如 ScrapeCreators)获取,需要单独的 API key 和账户余额。如果余额不足会直接报 402,不是配置错了。

## 官方 trending 接口(如果可用)

部分数据聚合网关(如 AIsa 之类的服务)会包装平台官方的 trending 端点(例如 X 按地区返回真实趋势榜,不需要种子词),这是比"自己想几个关键词去搜"更纯粹的自底向上信号源,但通常是按次付费——即使单价很低(可能只有几厘钱一次),使用前也要按"先说明范围和预估花费,拿到明确批准"的原则处理,不要因为便宜就默认可以调用。

## 中文平台:小红书/抖音/微博

- 小红书没有公开 API,依赖本地浏览器自动化 + 真实账号登录态,是最重的一档,不要轻易假设能直接调用。
- 抖音的官方工具"巨量算数"(trendinsight.oceanengine.com)对个人账号免费,但只有网页看板,没有可编程的 API,拿不到就老实说拿不到,不要用其他来源的数据冒充。
- 微博指数类工具官方 API 偏企业向,个人自助路径不稳定。
- **不要用"讲某平台运营趋势"的第三方分析文章当作该平台的实际热帖证据**——那是二手转述,不是原始数据,证据强度差一个量级,如果只有这类来源,如实标注信息来源类型,不要包装成"平台热帖"。
