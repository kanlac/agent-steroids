# Write Blog

将录音稿、口述笔记或零散想法转化为符合作者风格的博客文章。

## 写作风格

读取 [references/voice-dna.md](references/voice-dna.md) 了解作者的完整写作风格档案，包括语言特征、结构偏好、禁用表达。**每次写作前必须读取。**

## 工作方式

写作有两种模式，根据素材的准备程度选择：

### 模式一：素材已就绪（录音稿、口述笔记）

用户已经有了成型的想法，直接进入写作。

**理解输入**：录音稿是文章的灵魂——里面有作者的真实想法、情绪、结构倾向。错别字和口误不重要，重要的是意会作者想表达什么、想按什么顺序讲。如果用户同时指向了技术素材（代码仓库、文档、项目目录），先完整阅读这些素材，理解细节后再动笔。

### 模式二：从选题/调研到成文（对话式写作）

用户没有完整成型的想法——可能完全没题目（「想想写什么」），也可能只有一个模糊方向（「聊聊 XX 这件事」）。这种模式下，对话过程本身就是选题、构思、打磨的过程。**不要跳过对话直接出稿**。

完整工作流分四个阶段：

**阶段 1：找素材（用户没题目时）**

如果用户连题目都没有，先扫一遍他最近的素材库：

- Daily notes（最近 1-2 周）
- Memory 索引（user / project / feedback）
- Vault 中最新的卡片/笔记
- 最近的对话上下文

从中提炼 3-5 个候选话题，按「故事弧完整度」「观点强度」「利他价值」「平台发布限制」等维度排序，抛给用户挑。**不要只列标题，每个话题附一两句话说明它的切口和潜力**。

用户挑掉一些之后，根据他的反馈再补一轮——如果用户说「都不太想聊」「让你提问」，进入阶段 3 主动提问。

如果用户一开始就有明确方向，跳过此阶段，直接进阶段 2 或 3。

**阶段 2：调研（话题确认后）**

围绕选定的话题做调研——搜社区讨论、读相关文档、对比方案、查数据。目标是帮用户建立全景理解，**不急着下结论**，也不急着替他形成观点。

**阶段 3：提问漏斗（核心阶段，不要赶）**

这是整个对话式写作中最重要的阶段。**宁可多聊十轮，也不要急着收敛**。过早收敛 = 素材不够 = 文章单薄。

每轮抛出 4-6 个不同角度的问题，按维度分类——「情感/感受」「具体场景回忆」「人际故事」「反面/对立面」「价值观」「类比联想」。**让用户挑感兴趣的回答，不强求全部回答**。

用户回答完一轮，根据回答继续追问。追问方向：
- 把模糊表述变具体：「你说 XX，能举个例子吗？」
- 挖反面：「有没有反过来的时候？」
- 挖转折点：「什么时候开始这么想的？之前是怎么想的？」
- 挖金句：用户说出精彩的话时，顺着那个方向再深挖一层

**判断是否可以进入阶段 4 的标准**：至少完成 8-10 轮有效对话，且已经收集到 3 个以上具体场景/故事、1-2 个反直觉发现或个人洞察。如果素材还不够丰富，继续问，不要急。

**阶段 4：大纲迭代（多轮）**

**不要一次出初稿**。先出大纲——标题候选、钩子建议、主体框架、结尾候选，每部分让用户确认或调整。可能要迭代两到三轮，每轮都让方向更准。

大纲迭代时主动提供选项（A/B/C），让用户选比让用户从零想更省力。

确认完整大纲后再动笔写初稿。

**写作技巧：反直觉对比结构**

作者偏好的一种结构是——每一节先给「直觉的做法（看上去合理但其实错的做法）」，再给「更好的做法」。这种对比让读者更容易代入、更有「啊原来如此」的反转感。适合用在「实战经验类」「踩坑总结类」文章。

### 通用规则

**图片规划**：写作时同步规划图片插入位置，用 `> 📌 图片建议：...` 标注。图片要均匀分布在各章节，避免集中堆放。图片类型包括：截图、对比图、代码截图、产品界面、第三方生成的插图等。需要画信息图、对照表、原理示意图时，读取 [references/diagramming.md](references/diagramming.md) 了解作者的制图品味和已验证的出图流程。

**自检**：初稿完成后，对照 voice-dna.md 中的禁用表达清单和结构偏好做一轮自检，修正后再呈现给用户。

## 受众意识

文章面向混合受众——有技术背景的读者和非技术读者并存。技术概念需要用类比解释清楚（「你可以把它想象成...」），但点到为止，不过度展开成教程。信任读者的理解力。

## 文件与标题约定

- **文件名即大标题**：正文中不再写 `# 标题`，Obsidian 的文件名就是文章标题
- **大标题属性**：当标题含有 Obsidian 文件名不支持的字符（如冒号 `:`）时，在 frontmatter 中用 `大标题` 属性写完整标题，文件名用替代字符（如 `-`）
- **小标题**：写在 frontmatter 的 `小标题` 属性中，不写在正文里
- **正文直接开始**：frontmatter 之后紧接正文第一句

## Frontmatter

文章使用 Obsidian frontmatter：

```yaml
---
writing: true
publish-date: YYYY-MM-DD
大标题: 含冒号等特殊字符的完整标题（可选，仅在文件名无法完整表达时使用）
小标题: 副标题写在这里
post_tags: "#标签1 #标签2 #标签3"
---
```

注意：
- 缺 `writing: true` 文章不会进入 vault 的写作 base，必填
- `post_tags` 是单行字符串格式，用空格分隔带 `#` 前缀的标签，不是 YAML 数组
- 发布用的标签属性是 `post_tags`，不是 `tags`。`tags` 是 Obsidian 的原生属性，会影响 vault 内的标签系统，而 `post_tags` 是纯文本字段，仅供发布平台使用
