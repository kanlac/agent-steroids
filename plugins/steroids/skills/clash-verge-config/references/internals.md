## 1. 保留字段

`enhance()` 最后一步 `merge_default_config` 用 Verge 自己的 clash 配置覆盖脚本输出，受影响的典型字段：

- `external-controller`：启用开关开 → 用 clash 配置里的值；关 → **强制写空字符串**（即没有控制器）。
- `secret`、`mixed-port` / `socks-port` / `port` / `redir-port` / `tproxy-port`、`log-level`、`external-controller-cors`、`external-controller-unix`。

官方文档（Merge 页）原文：被 Clash Verge 覆盖的配置无法被成功覆盖，程序必须自己控制这些部分以维持正常功能（例如 `mixed-port`、`log-level`、`external-controller` 等）。

要改这些 → 改第 2 节的「持久化 clash 配置文件」，不要写在扩展脚本里。

## 2. 配置文件角色与位置

应用数据目录（macOS）：`~/Library/Application Support/io.github.clash-verge-rev.clash-verge-rev/`
（Windows/Linux 路径不同，见官方文档；用「应用数据目录」这个概念去定位。）

| 文件 | 角色 |
|---|---|
| `config.yaml`（头部 `# Generated by Clash Verge`） | **持久化 clash 配置**（源码 `IClashTemp`，`dirs::clash_path()`）。`external-controller`/`secret`/端口等保留字段的真正落点。启动时读取并 `guard()` 校验，改它要在 App 停止时改。 |
| `clash-verge.yaml` | `enhance()` 生成的**运行时配置**，真正喂给内核（`-f` 指向它）。每次重新生成时覆写。 |
| `verge.yaml` | App 设置。含 `enable_external_controller`（external controller 启用开关）、`enable_dns_settings`、`enable_tun_mode` 等。 |
| `profiles/` + `profiles.yaml` | 订阅 profile、全局/订阅级扩展配置(Merge)与扩展脚本(Script)。`profiles.yaml` 的 `current` 指向当前 profile，其 `option.script` 指向当前生效的脚本文件 uid。 |

注意：`guard_external_controller` 解析时，`:9097` 会被补成 `127.0.0.1:9097`（**不是** `0.0.0.0`）。要局域网可达必须显式写 `0.0.0.0:9097`。secret 为空会被替换成占位值。

## 3. enhance() 生成管线与源码位置

`src-tauri/src/enhance/mod.rs` 的 `enhance()`：

```
process_global_items   # 全局 Merge → 全局 Script
process_profile_items  # 订阅级 rules/proxies/groups → Merge → Script
merge_default_config   # ★ 用 clash 配置覆盖保留字段（external-controller 按开关，其余无条件）
apply_builtin_scripts → cleanup_proxy_groups → use_tun → use_sort → apply_dns_settings
```

- 启动时 `config/config.rs` 的 `generate_and_validate()` → `Config::generate()` → `enhance::enhance()` → 写 `clash-verge.yaml` → 校验 → 内核加载。**所以重启 = 重新生成。**
- 触发 `enhance()` 的命令：`feat::enhance_profiles()` / `CoreManager::update_config_forced()` 等，都由 Tauri 命令（前端 IPC）或 App 事件调起，**无对外 HTTP/CLI 入口**。
- deeplink `clash://install-config?url=...`（`utils/resolve/scheme.rs`）只导入订阅。
- `enable_dns_settings` 为真时，`apply_dns_settings` 会用应用数据目录里的 `dns_config.yaml` **覆盖** dns 段——所以 dns 也半受 Verge 管，脚本里设的 dns 可能被盖。

## 4. mihomo external controller API

内核 RESTful API（默认无 `-ext-ctl` 标志时，监听地址取自配置文件的 `external-controller` 字段）。鉴权：`Authorization: Bearer <secret>`。

常用端点：

```bash
SECRET=<your-secret>; BASE=http://127.0.0.1:9097
curl -s -H "Authorization: Bearer $SECRET" $BASE/version
curl -s -H "Authorization: Bearer $SECRET" $BASE/configs          # 当前配置
curl -s -H "Authorization: Bearer $SECRET" $BASE/connections      # 实时连接：含每条的 rule / rulePayload / chains
curl -s -H "Authorization: Bearer $SECRET" $BASE/proxies          # 节点/策略组
# 热重载（按文件路径，path 须内核可读的绝对路径）：
curl -s -X PUT -H "Authorization: Bearer $SECRET" "$BASE/configs?force=true" -d '{"path":"/abs/clash-verge.yaml"}'
```

- `PUT /configs` 重载的是内核「当前配置文件」，不跑 Verge 的 `enhance()`。要套用扩展脚本改动仍需先重新生成（重启），或自己生成完整配置后用 `{"payload":"<整段 yaml>"}` 灌入。
- 内核可能同时被 Verge 用 unix socket 控制（`-ext-ctl-unix`），那条不影响 TCP 控制器。

## 5. external-ui 自托管 Web 面板

让内核用 HTTP 在 `/ui/` 托管面板，避免在线 HTTPS 面板连 HTTP 控制器的混合内容拦截。

1. 准备面板静态文件目录（例：MetaCubeXD）：
   ```bash
   APPDIR=~/Library/Application\ Support/io.github.clash-verge-rev.clash-verge-rev
   mkdir -p "$APPDIR/ui"
   curl -sL -o /tmp/ui.zip https://github.com/MetaCubeX/metacubexd/archive/refs/heads/gh-pages.zip
   tmp=$(mktemp -d); unzip -q /tmp/ui.zip -d "$tmp"
   cp -R "$tmp"/metacubexd-*/. "$APPDIR/ui"/      # 注意用 /. 拷贝目录内容
   ```
2. 在持久化 clash 配置文件里加 `external-ui: ui`（相对路径相对内核 `-d` 目录，即应用数据目录）。
3. 重启 App（触发重新生成 + 内核加载）。
4. 访问 `http://<host>:<port>/ui/`，面板里填 secret（地址同源自动带出）。

验证：`curl -s -o /dev/null -w '%{http_code}' http://127.0.0.1:9097/ui/` 应为 `200`。

## 6. 常见坑

- **混合内容**：HTTPS 在线面板（yacd.metacubex.one 等）连 HTTP 控制器会被浏览器拦截，需手动「允许不安全内容」。用第 5 节的 `/ui/` 自托管可绕开。
- **连自身 VPN IP 的 hairpin**：在同一台机器上 curl 它自己的 Tailscale IP 常超时（用户态 netstack 自连不可靠），**不代表服务没起**——socket 绑 `0.0.0.0` 时局域网/别的设备能连就说明正常，换别的设备验证。
- **TUN 与 VPN 路由共存**：Clash TUN 常用 `0.0.0.0/1` + `128.0/1` 拆分劫持默认路由；Tailscale 的 `100.64.0.0/10` 是更具体路由、不被劫持，二者可共存。排查时 `netstat -rn` 看具体网段落到哪个接口。
- **改 config.yaml 没生效**：多半是在 App 运行时改的、被回写覆盖了。先退出 App 再改。
