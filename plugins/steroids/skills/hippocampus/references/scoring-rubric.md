# 评分卡 —— 让分数在不同模型、不同次运行之间可复现

> **rubric_version: 2.5**。产出的报告须带上此版本号（写进 meta 的编号/样本行）；不同版本评分卡下的分数不可直接比较。

## 通用原则

1. **能机械算的，用确定公式**（行数、大小、token、断链、截断）——谁跑、跑几次都得同一个数，由 `scripts/score-mechanical.py` 算出，不靠模型估。
2. **要判断的，只对候选做裁决**——脚本先生成候选清单，agent 对每条候选做「是/否真缺陷 + 定级」。对固定清单做分类，远比自由狩猎收敛。
3. **「从 100 扣分」而不是「凭感觉给分」**——固定的缺陷类型 + 每类扣多少 + 判定例子。
4. **反通胀纪律**：拿不准算不算缺陷时不扣（保守）；绝不为凑数制造或忽略缺陷；矛盾维度先排除「作用域覆盖」这类伪缺陷。

每一维都从 100 起扣，扣到 0 封底。

## 三段式管线：机械盘点 → 候选生成 → 语义裁决

飘有两个来源：**判什么**（裁决口径）和**扫哪儿**（覆盖范围）。管线把两者都机械化：

1. **机械盘点**（脚本，零飘）：行数/大小/token 估算、指令文件超行扣分、auto-memory 截断扣分、软链接去重。**同时产出 `scope_manifest`（范围清单）**——指令文件、auto-memory 文件（各项目 `~/.claude/projects/<slug>/memory/*.md`）、指令文件指向且实际存在的文档、skills 清单。**打分只覆盖清单内的文件：不越界、不漏。** 两次运行范围完全一致，覆盖漂移归零。
2. **候选生成**（脚本，零飘）：断链候选、时效标记候选、含糊线索候选、同主题矛盾候选对，外加 **`rule_inventory`（规则清单）**——机械抽取的规范性条款（不要/必须/统一/不超过…）。
3. **语义裁决**（agent）：逐条候选判「是不是真缺陷、属哪类、按表扣几分」，记入账本。**矛盾维度的「规则 vs 实例」核对是封闭的**：只拿 `rule_inventory` 里的条款逐条对照 `scope_manifest` 内的文件核实例，不做开放搜索；补充性自由扫描**仅限指令文件内部**（找规则对规则的冲突）。auto-memory 文件属预置侧，其内容同样按新鲜度/可用性裁决。

## 记账：一本账，两种切法

打分的原子单位是一条 **finding（缺陷证据）**，这本账是唯一事实源——分数、报告证据、处方笺、治疗确认书的行，全部由它推导，不允许第二份账：

```json
{
  "id": "f-012",
  "dimension": "contradiction",
  "deduction": 12,
  "surfaces": ["global", "skill:web-access"],
  "evidence": [{ "ref": "file:line", "quote": "原文" }],
  "confidence": "high | medium | low",
  "fix": { "action": "reconcile", "note": "以哪条为准由用户定", "effect": 3 }
}
```

**汇总 = 同一矩阵的边际。** 每条 finding 按（维度 × 类型）落进 2 类型 × 4 维度的矩阵格子：

- **格子分** = 100 − Σ 该格扣分（封底 0）。天然 N/A 的格子跳过（如「截断」只存在于预置侧 auto-memory）。
- **维度分** = 该维度两个格子按预置:外部 = 5:5 合并（一侧 N/A 时取另一侧）。
- **类型分（预置/外部）** = 该类型四个格子等权平均。
- **总分** = 预置 : 外部 = **5:5**。
- **跨类型矛盾**（预置规则 ⚔ 外部 skill）：维度上全额记入「矛盾」，类型上扣分**对半分摊**到两侧格子——不双算，总分守恒。

因为三个视图（维度/类型/总分）都是同一矩阵的边际，它们永远自洽。

## 外部侧按密度折算（仅新鲜度、可用性）

预置层每一行都给每轮交税，缺陷按**绝对条数**扣。外部层按需取用，规模大不该吃亏——100 个 skill 里 3 条断链，明显健康于 5 个 skill 里 3 条。所以外部侧的新鲜度/可用性真缺陷先折算成**每 10 个条目的缺陷数**（skill 按个计、文档按篇计），再套各自对照档。**矛盾不折算**——矛盾稀少而严重，密度化会稀释它。

## ① 体量 Bloat（机械，最可复现）

**分两种失效模式，别混（依据 Claude Code 官方 memory 文档）：**

**(a) 指令文件膨胀**（`CLAUDE.md` / `AGENTS.md`）——它们每次**全量拼进上下文、不会被截断**；太大的代价是**占 token + 遵循度下降**（官方：指令越长越容易被忽略）。200 行是官方对单个 `CLAUDE.md` 的建议上限，按行数扣：

```
超行扣分 = min(45, Σ_每个指令文件 max(0, (L−200) / 20))   # 每超 20 行扣 1
```

**(b) auto-memory 硬截断**（**仅 Claude Code**：它自己累积的那套记忆）——官方明确每次只载**前 200 行 或 25KB（谁先到）**，超出部分**直接不进上下文、这一轮完全不生效**。这才是真正的「截断」：

```
截断扣分 = round(60 × 被丢弃比例)   # 被丢弃比例 = 1 − (200行/25KB 内载入量 / auto-memory 总量)
```

Codex 等没有 auto-memory 机制的 agent，此项记 0、不适用。

**体量 = 100 − 超行扣分 − 截断扣分**（封底 0）。对照档：

| 分 | 状态 |
|---|---|
| 90–100 | 所有指令文件 ≤200 行；无 auto-memory 截断 |
| 75–89 | 个别文件轻微超（≤300 行）；无截断 |
| 60–74 | 明显超标（单文件 300–500 行）；无/临界截断 |
| 40–59 | 严重超标（>500 行）或 auto-memory 已截断（<25% 被丢） |
| <40 | 巨型指令文件 + auto-memory 截断（>25% 从未加载） |

## ② 可用性 Usability（判断，按缺陷条目计数）

**不做全文件自由分类**——那是漂移的最大来源（实测两个模型一个判 0 条废话、一个判 83 条）。流程：以脚本的含糊线索候选为起点，外加**限量补漏**（≤10 条，每条必须引用原文；配额用完宁可不补）。对每条候选/补漏裁决，确认为缺陷的按**条目**扣分——一个 bullet / 一个段落算一条，不按物理行：

| 缺陷类别 | 判定例子 | 每条扣 |
|---|---|---|
| 通用废话 | 「写整洁代码」「注意性能」「保持可维护」 | −3 |
| 无法执行 | 「合理处理」「视情况而定」「注意边界情况」 | −3 |
| 可推断项 | 技术栈、`package.json` 能看出的、显而易见的目录约定 | −3 |
| 错位 | 只关乎单个 skill/工具的**教训本体**（步骤、参数表、命令序列、转义表）整段内联在全局预置（修复 = 移进对应 skill） | −5 |

「改变 agent 下一步动作」的决策项不扣（如「本项目走自建 git host，不是默认 github」「删历史用 filter-repo 不用 filter-branch」）。**指针不算错位**：一两行「凡 X 场景，先用 skill Y」是全局路由器的正当职责。判定测试：把这段删掉，对应 skill 能原样恢复这份能力吗？**能恢复 → 教训本体住错了地方，算错位；不能（它的职责就是把你带去那个 skill）→ 指针，不扣。** 一段里指针+内联细节混排时，只有超出指针职责的细节部分算错位。同类封顶 −24，总封底 0。对照档（sanity check）：90–100 ≈ 0–3 条；75–89 ≈ 4–8 条；60–74 ≈ 9–14 条；40–59 ≈ 15–20 条；<40 更多。外部侧按密度折算同前。

## ③ 新鲜度 Freshness（机械 + 判断，按缺陷扣分）

以脚本的断链候选、时效标记候选为起点逐条裁决（区分真引用 vs 文档举例）：

| 缺陷类型 | 怎么认（机械项可脚本核） | 每处扣 |
|---|---|---|
| 断链：引用指向已删/改名的文件 | 脚本候选 + agent 确认是真引用 🔧 | −8 |
| 失效时效声明：「临时/WIP/待官方修复/currently-using-X」但对应事已 ship | 脚本候选 + 语义确认 | −6 |
| 已完工记录：git 历史已有的完工/PR/进度追踪 | 语义 | −5 |
| 过期数据：带日期的旧数值，明显不再代表现状 | 脚本候选 + 语义确认 | −4 |

**去重**：同一行/同一事项的多个坏引用算**一处**缺陷（一段话里两个失效路径 = 1 处，不是 2 处）。

**auto-memory 内容的裁决口径**：判一条笔记的标准是**它的价值是否依赖「当时」**。价值在于追踪进行中状态的——「Current Focus as of <几个月前>」（过期数据）、已完成迁移/调试的过程记录（完工记录）——工作一 ship、日期一过就是缺陷。价值在于可迁移结论的——架构教训（如「409 冲突用每 agent 独立 bot 解决」）、用户画像、长期偏好——**不论多旧都不扣**。判据一句话：把日期抹掉，这条笔记还成立吗？成立 = 教训（留）；不成立 = 记录（扣）。

**锚定例**：真断链 = 正文**指引 agent 去用**的路径实测不存在（如「认证已保存在 `~/.notebooklm/....json`，开始前可先验证」而该文件不存在——这是要照做的指令，路径没了就是坏的）；文档举例 = 讲规则时举的示例路径（如「例如 `docs/260603-user-journey.md`」「worktree 命名如 `~/Documents/repo-name`」）——不算缺陷。

分数 = 100 − Σ扣分（同类封顶 −24）。对照（预置绝对条数；外部先按密度折算）：90–100 = 0–1 处；75–89 = 2–3；60–74 = 4–6；40–59 = 7–10；<40 = 10+。

## ④ 矛盾 Contradiction（判断，跨表面，按对扣分）

以脚本的同主题候选对为起点，**再做一轮补充性自由扫描**。先排除伪矛盾：项目覆盖全局、显式例外、带条件的作用域差异（如「默认用 github，但某项目用自建 host」）**不算矛盾**。只数「同一场景、无作用域区分、给出相反指令」的**真冲突对**：

| 严重度 | 判定 | 每对扣 |
|---|---|---|
| 硬冲突 | 两侧都是明确 always/never 的**规则**，指向同一场景却相反 | −20 |
| 软/风格冲突 | 约定不一致（如日期前缀 `yyMMdd` vs `YYYYMMDD`） | −12 |
| 规则 vs 实例（自我违反） | 一处立了规则，另一处自己违反（如「不要硬编码用户名路径」⚔ 同文件里一条硬编码的绝对路径）。**不算硬冲突**——只有规则对规则才算硬 | −12 |
| 潜在冲突 | 可能冲突但存在条件差异 | −6 |

**按规则去重**：「规则 vs 实例」中，同一条规则不论被多少个文件违反，**合并为一条 finding**（证据列全部实例，扣一次）——缺陷是「这条规则失守」这一个治理问题，不是 N 个独立矛盾；不合并的话一条风格规则就能压垮整个维度。不同规则才分开计。

**同类封顶**：硬 / 软 / 自我违反 / 潜在，每类合计封顶 −24（与其他维度一致）。

分数 = 100 − Σ扣分（跨类型的对半分摊进两侧格子）。对照：90–100 = 0 处；75–89 = 1 软；60–74 = 1 硬或 2 软；40–59 = 2–3 硬；<40 = 大面积冲突。

## 可复现性的现实

- **体量、候选生成** = 脚本 → 跨模型/多次运行**完全一致**。
- **候选裁决**（断链真伪、废话计数、完工/失效、矛盾定级）= 判断，但对固定候选做分类后，不同模型会**明显收敛**，残余小幅波动来自矛盾的补充性自由扫描。报告仍标「方向性参考」——评分卡把区间压窄，不假装消灭波动。
- **语义裁决必须用中档及以上模型**。实测低档模型系统性失真：一边给全文 0 缺陷盖章、一边全文重判出 83 条，同一维度差出 74 分。机械段（脚本）用什么模型跑都一样。
- **残余方差来自检出深度，不是裁决口径**（实测四轮跨厂商双模型：总分差 12.5→18.8→3.9→5.6，裁决规则钉死后两边找到的都是真缺陷、只是子集略有不同）。总分按 ±5 左右的区间理解。
- **正式体检的标准做法：双模型（或同模型两次）独立跑，取账本并集重算**——并集消掉漏检方差，是当前口径下最完整的分。单跑一次视为分数上界（漏检只会让分虚高）。
- 追踪趋势：同一 rubric_version + 尽量同一模型，纵向对比才有意义。
