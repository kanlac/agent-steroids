# 诊断报告 —— 打分与渲染

如何把一次扫描变成「记忆精神科确诊书」。视觉模板是 `assets/diagnosis-template.html`；这篇是它背后的评分细则和填充指引。

## 原则：没有证据就不扣分

每个分数都是一个断言，每个断言都要有凭据。在任何维度扣分之前，先拿到具体的 `file:line` 和证明它的原文引用。报告在每个维度下方内联展示这些引用——这正是让用户相信「诊断是从我真实的记忆算出来的、不是套模板」的东西。一个没有引用行的维度分数是个 bug。

信号分两种，别把它们混为一谈：

- **🔧 机械（可复现）**——行数、文件大小、200 行规则、每轮 token 估算、断链检查、`@AGENTS.md` 导入检查。谁重跑都得同样的结果。
- **🧠 语义（判断）**——「这一行不改变任何决策」「这条笔记过时了」「这两条规则矛盾」。这是 Agent 品味所在的地方。把它标成判断，别装成度量。

## 四个维度

每个回答一个不同的问题——保持互不重叠（太大 / 没用说不清 / 过时 / 打架）。

- **① 体量 Bloat**——只看大小。指令文件（CLAUDE.md/AGENTS.md）每轮**全量注入、不会被截断**：按 200 行规则、总字节、每轮 token 估算衡量，超标的代价是 token 税 + 遵循度下降。auto-memory（仅 Claude Code）才有硬截断：每次只载前 200 行或 25KB，超出部分完全不生效。纯机械，由 `scripts/score-mechanical.py` 算。对任何单文件适用，无论预置还是外部。
- **② 可用性 Usability**——已有的内容里，有多少真能改变一个决策。标记通用废话、能从 repo 推断的内容、以及**含糊到无法执行的指令**。主要靠语义，辅以机械（重复检测、样板套话）。注意：这一维分析的是**用户文件里已有的内容**，如实说它「含糊、无法执行」即可，不要给它套上「医嘱」之类的词——诊所开出来的才叫医嘱，被分析的现有内容不是。
- **③ 新鲜度 Freshness**——是否还成立。指向已删/改名文件的死路径（机械）、已完工的进度记录和失效的「临时/WIP/currently-using-X」声明（语义）。
- **④ 矛盾 Contradiction**——有没有东西和另一处冲突，**包括跨预置和外部**。把冲突**成对**呈现，每一侧引用各自的 `file:line`。这是信号最强、最有说服力的发现——用户会「啊，这俩我确实都写过」——所以给它一块独立醒目的版面，做成左右并排（两栏、显示行号；demo 用假行号也行）。

## 汇总

```
每维度的证据
   → 表面分：全局记忆 / 项目记忆 / 技能 / 文档（各 0–100，直接展示）
   → 预置分（全局+项目）和 外部分（技能+文档）
   → 总分 = 预置 : 外部 = 5:5（0–100）+ 等级带
```

默认 5:5 加权——不预设哪一层对某个用户更重要。表面用用户看得懂的名字（全局记忆 = 那个全局 CLAUDE.md），可见报告里绝不写「上半区/push」这种词。

等级带（精神科诊断口径，措辞可调，好玩但不刻薄）：

| 分数 | 病情分级 |
|---|---|
| 90–100 | 认知清明（脑回清奇） |
| 75–89 | 轻度信息过载 |
| 60–74 | 记忆囤积倾向 |
| 40–59 | 记忆囤积障碍（伴脑雾） |
| <40 | 重度脑雾 · 上下文失忆 |

叙事是精神科（在诊断一颗大脑），所以等级带保持这个语域——认知、负荷、囤积、脑雾、失忆——不要用体重隐喻。

始终打一行小字声明：分数是**方向性参考，不是精确度量**——机械项可复现，语义项取决于当次判断；真正有价值的是处方，不是数字。

## 只产数据，不写文案，不改结构

模板是 **DATA 对象驱动**的：文件顶部有一个 `DATA` 对象，页面的 JS 据此自己渲染——等级带按总分自动高亮、配色按分数分档（含健康绿档，好分数不显示成发黄警告）、截断叙事只在真被截断时出现、处方/矛盾条数由数组长度决定。所有固定文案（标题、副标题、引导语、免责声明、确诊句式、等级带名称）和渲染逻辑都写死在模板里。

Agent 运行时**只产出那个 DATA 对象**（分数、证据、矛盾对、处方数组、是否截断等纯数据），替换进模板顶部即可，**不手改 HTML、不临场编文案、不搬 CSS class**。需要改措辞或视觉时改模板本身，不在运行时改。

**DATA 由账本聚合而来。** 打分阶段的唯一事实源是 findings 账本（见 `scoring-rubric.md` 的「记账」）：DATA 里的 `dimensions[].evidence`、`contradictions`、`prescriptions` 都是账本条目的投影，各分数是账本按矩阵边际的聚合——不允许出现「报告里有但账本里没有」的证据或处方。`meta` 的编号/样本行要带上评分卡版本（如 `rubric v2`），跨版本分数不可直接比较。

## 报告的板块（模板要填的数据）

模板是一份精神科病历（确诊书）。每一块都用真实扫描数据填满——产出的报告里不留占位符：

1. **主诉 / Hero**——总分、确诊标题、副行、一句诊断，以及震撼数据（总大小、每轮 token 税、多少比例从未加载）。**「确诊：〈等级带〉」的标题由模板从等级带自动渲染，`diagnosis.line` 只填补语**（如「伴 31% 上下文失忆」「无超载 · 伴 6 处指令互搏」），不要再带「确诊：」或等级带名，否则标题会重复。大标题要保持好读，别挤成难看的多行块。
2. **两类记忆记分**——预置 / 外部 下的四个表面分。
3. **四维诊断（分数即证据）**——每个维度的分数，下方铺开它扣分的引用行。
4. **矛盾专区**——成对的冲突，左右并排带行号。
5. **处方笺**——西药（机械/高把握）和中药（判断/中低把握），每项带剂量（多少条）、把握程度、预期疗效（+X）。中药措辞是「供你定夺」，不是命令。在诊断报告这一页，处方只是预告：突出 1–3 个最值得关注的项并说明原因即可，不必写全，完整清单在治疗确认书里。
6. **疗效预测**——照做前后对比：总分、token 税、记忆是否不再超载。

**用户可见文案用大白话**：内部机制叫「截断」（`truncated`——只发生在 auto-memory：前 200 行 / 25KB 之外的部分不生效），但报告里对用户说「超载 / 没超载」——auto-memory 吃太饱＝「记忆超载，X% 没加载」；没有 auto-memory 或在限内＝「没超载」或「记忆基本清明」。指令文件的膨胀不叫超载，说「太长、遵循度下降、每轮多烧 X token」。不要在用户可见处写「截断 / 全量加载」这类黑话。

## 处方 → 确认交接

处方不是终点。它的每一项会成为治疗确认书（ReviewTable）的一行。报告结尾给一个清晰的入口进入确认步骤（按钮放在整页最后），在用户确认之前不执行任何改动。见 `references/review-table.md`。

## 扫描范围与跨 agent 探测

扫的是**此时此地这个 Agent** 的记忆，不跑去扫别的项目。自动探测存在哪些记忆文件，有啥扫啥，别假设一定是 Claude：

- 预置层：全局 `~/.claude/CLAUDE.md`、项目根的 `CLAUDE.md` / `AGENTS.md`（Codex 等 agent 读 AGENTS.md）、Claude 的 auto-memory（存在才算）。
- 外部层：可触达的 skill 及其 description、指令文件指向的文档。

环境很大时按 SKILL.md 的「并行取证 + 单点综合」扇出 subagent，且对文档**抽样**而非逐字读全，给成本兜底。

## 输出目录约定

报告写到约定目录，按时间戳分子目录（不覆盖历史，可看健康度趋势）：

- **Mac/Linux**：`~/Downloads/hippocampus/<YYYY-MM-DD-HHmm>/`
- **Windows**：`%USERPROFILE%\Downloads\hippocampus\<YYYY-MM-DD-HHmm>\`

每个子目录放 `diagnosis.html` + `review-table.html`，单文件、内联、离线可开。交付前确认每一块都由真实数据填满、矛盾对引用的是真实冲突行。

## 优雅失败

- 没找到任何记忆文件 → 友好提示，不报错。
- 约定目录不可写 → 退到临时目录，并明确告知最终路径。
- 无浏览器（SSH/headless）→ 直接给文件路径让用户自己打开。

## 脱敏与隐私（生产级红线）

- **全程本地、不联网、不外传**：只读本机记忆文件，报告只写本地。这既是红线，也是对外最好的信任卖点——用户的记忆一个字都不离开自己的电脑。
- **完整报告是私密的**：它内联了记忆文件的**真实原文引用**，可能含私密项目名、含用户名的路径、甚至密钥。报告里要有一行提示：完整报告含记忆原文，对外分享请只用「分享卡」。
- **分享卡是唯一对外物**：只带总分、病情分级/等级带、四维分数、处方数这类**非敏感聚合信息**，绝不带证据引文、文件路径、用户名。
