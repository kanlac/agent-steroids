# 吸收新知识 —— 让下一次行为改变

用于会话末提取教训，或用户当场要求「记住 / 沉淀 / 改进 skill」。用户的请求已经授权落地；不要生成体检报告或治疗确认书。

## 先判是否值得记

先问：**下一个 Agent 会因此做出不同决定吗？** 不会就不记。会，再选唯一主人：

- 已有可靠来源、已完工记录、一次性上下文、可直接推断 → 不记。
- 单一工具或流程的教训 → 重构进对应 skill 或工具描述。
- 跨领域、几乎每轮成立的硬约束 → 预置记忆。
- 偶尔需要但重新推导昂贵的知识 → 外部 reference / 文档。

Auto-memory 可作为入口，但不是天然终点：内容若已有正确归属，就合并过去；长期偏好可保留；进度快照在失效后删除。只看质量和用途，不按自动/手动贴标签。

## 重构，不追加

1. 先用一句话命名未来行为；说不清就继续提炼。
2. 找到放任旧错误发生的决策点：触发、路由、边界、反例或验证。
3. 用最短充分表达重写该处；一行够就不写一段，能替代旧文就删旧文。
4. 优先改善接口、schema 或参数；只有真实歧义才加 2–3 个例子。
5. 几句话留正文；可选、很长或易变化的细节才进 reference。
6. 检查断链、重复、私密信息、硬编码路径、行数与 manifest / README 一致性。

## 常见落法

- 工具选错 → 收紧路由条件，不写一篇事故复盘。
- 用户纠偏 → 改掉导致误判的那条规则，并删附近重复说法。
- 来源很长 → 提炼一条原则或少数锚定例，不复制来源目录。
- 同一事实散落多处 → 选一个主人，其余改成必要指针或删除。

公开 skill 不得吸收个人路径、账号、客户或项目私有假设。
