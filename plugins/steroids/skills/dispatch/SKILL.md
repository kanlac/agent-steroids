## 先做

1. **读 `--help`**。这些 CLI 迭代很快，参数名、默认值、子命令都在变。本文档记的是
   问题的**形状**，不是某一版的参数表；真正的调用方式以你当下看到的 help 为准。
2. **探活**。换 CLI、换模型、换机器之后先跑一次，几秒钟排除掉一整类「空输出」的误判：

   ```bash
   <cli> run -m <provider/model> "只回答两个字：收到" < /dev/null
   ```

   命令按当下 help 调整，但 `< /dev/null` 大概率还是要留着。

## 五类会静默失败的坑

这些 CLI 出问题时**通常不报错，只是安静地什么都不输出**，退出码还是 0。
看起来完全像「模型没有话说」。遇到空输出，按下面五类依次排除。

### 一、stdin 没有关掉

现象：零字节输出，无报错，进程一直挂着或立刻退出。
原因：CLI 在等标准输入。
排查：命令末尾加上 `< /dev/null`。这一条至今对 Codex 和 OpenCode 都成立，
是空输出最常见的原因，先查它。

### 二、权限沙箱把它拦住了

现象：输出里有 `permission requested ... auto-rejecting` 之类的行，然后**整轮中止**，
不出报告——模型不会绕开，也不会把已经得到的结论先交出来。
典型受害路径：`/tmp`（它想写验证脚本）、家目录下的配置、别的仓库。
排查：看 help 里有没有「自动批准权限」「跳过确认」这类开关；同时在提示词里
**指定一个它有权写的临时目录**，并明确要求「即使工具调用失败也要输出报告」。

跨目录的系统（代码在仓库、配置在 LaunchAgents、部署在另一个仓库）尤其容易撞这条。

### 三、输入长度墙

现象：提示词一长就只回一行标题或干脆空白，无报错。
注意这堵墙**未必在模型的上下文上限**——可能是 provider 或 CLI 这一层的限制，
配置里声明的 context 大小不作数。
排查：二分找出可用长度；更好的做法是**不要把源码塞进提示词**，让它自己去读文件
（见第二类），需要拆分时按文件或模块分批送。

### 四、provider 配额耗尽

现象：**跑到一半停下**。产出里只有过程旁白（「现在让我…」「接下来我要…」），
没有最终报告；退出码 0；真正的错误只出现在 stderr 末尾。
和「模型没话说」几乎无法从产出上区分。
排查：`grep -i "quota\|limit\|exceeded"` 看 stderr 末尾，通常会告诉你什么时候重置。

**这一类没法靠重试绕开**，只能换 provider/模型或等重置。所以派长任务之前，
先想清楚这一轮大概要烧多少——配额是按时间窗口计的，跑到一半断掉，
前面的钱已经花了，产出却是零。

**通用的减损办法：让它自己把报告写进文件**，而不是靠你在外面捕获 stdout。
中途夭折时，至少能拿回已经写完的那部分。

### 五、后台跑成了孤儿

现象：跑完没有任何通知，你只能轮询猜。
原因：命令末尾自己加了 `&`。
排查：用工具自带的后台机制（如 Bash 工具的 `run_in_background`），命令本身不要加 `&`。

## 派活之前

- **默认不划只读范围，信任模型自己探索**。指出入口文件和关注点即可

- **说清楚已经修过什么**，否则它会把你刚修完的再报一遍，你还得逐条辨认。
- **要求每条发现具体到文件和函数，并说明什么输入下出什么错**。泛泛的
  「建议加异常处理」既没有验证价值，也没法判断真假。
- **并行派多个实例时给不同侧重**，否则拿回三份雷同的东西。
- **续问用显式会话 ID，并等待上一进程退出**。`--continue` 只指向当前目录最近会话，
  多任务时会续错；同一 session 并发还会串线。OpenCode 的判定与恢复方式见
  `references/opencode.md`。
- **不要让两个实例同时写同一个仓库**。给每个一个独立目录。
  只读/调研类别急着「放到仓库外跑」——有些 CLI 会拒绝读 cwd 之外的路径，
  那样等于让它闭着眼审。**复制一份只读快照，让它在快照里跑**：它碰不到真仓库，
  又不触发跨目录拒绝，还顺带把它能读到、进而发给 provider 的范围钉死了。
- **沙箱可能禁网**。先替它把依赖装好，提示词里禁止联网命令、缺包只许报包名。

## 拿到结果之后

**先复现，再修**。模型可能假设对但理由错，也可能理由对但结论过头。能写出复现脚本的
写一个；写不出来的，至少手工构造一次触发条件。

**注意它自陈的边界**。好的报告会说「这部分我看不到」——那正是你要自己补的地方。

**分批送审通常比一次送全部有效**：既避开长度墙，也让它对每一部分保持注意力。

## 选谁干

用各 CLI 的 `models`/`--help` 查当下可用的清单，不要凭记忆。选型上的经验：

- 代码审查、安全相关，挑推理和安全能力强的模型。
- 要长输出（整文件重写、大批量生成），先看模型的**输出上限**——这是硬约束，
  不够的话再聪明也会被截断。
- 需要跨模型交叉验证时，让不同家族的模型各审一轮，比同一个模型审两遍有价值。
