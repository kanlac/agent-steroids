# cdp-chrome 共享浏览器接入层：需求文档

状态：需求阶段，未实施。本文只定义"要什么"和"不要什么"，不绑定当前 `plugins/chrome` 的实现细节；chrome 插件正在另一条分支重构，实现方应以本文为约束、以重构后的代码为基础。

## 1. 背景与问题

cdp-chrome 插件提供一份全局共享、带登录态的有头 Chrome，供所有 agent 会话使用。Chrome 本身是复用的，但**接入层不是**：插件把 chrome-devtools-mcp 注册为 stdio 型 MCP server，宿主（Claude Code）对 stdio server 的行为是每个会话启动时立即 spawn 一份、断开后不自动重连。

2026-09-09 在 16 GB 的 Mac mini 上实测：

| 项目 | 数值 |
|---|---|
| 并存的 Claude Code 会话 | 26 个（17 个为无终端 UI 的 Remote Control 会话） |
| 其中实际在用浏览器的 | 1 个 |
| 每会话接入层开销（npm 包装 + chrome-devtools-mcp 空闲） | 约 45 + 67 MB |
| 连上浏览器后单份 MCP 进程 | 约 134 MB |
| 接入层合计 | 约 2.8 GB，swap 9.2 GB 已用 8.6 GB |

问题不在 Chrome，在于"每会话一份接入进程，且不管用不用都起"。

## 2. 目标

用户原话："我希望这个东西是一个开销很小的工具，每个会话都能有，同时几乎不会增加内存负担。它是很常用的工具，我不想在需要用的时候想着手动打开。"

拆成可验收的目标：

- G1 **每个会话随时可用**：任何 agent 会话（含无 UI 的远程会话）不需要用户做任何开关动作就能操作共享 Chrome。
- G2 **未使用即零开销**：没有调用过浏览器的会话，不得为接入层持有任何进程。
- G3 **全机开销与会话数无关**：接入层在整机上的常驻内存是一个常数，不随并存会话数线性增长。
- G4 **多 agent 并行不互相干扰**：多个会话同时操作各自页面时，结果互不串扰。
- G5 **不需要人工维护**：崩溃、机器重启、Chrome 重启后，下一次使用能自动恢复到可用状态；不引入需要用户记得去启停的常驻服务。

## 3. 非目标

- 不追求多个 agent 对浏览器的真并行执行。串行排队可接受，但要有上界（见 N2）。
- 不追求"全机空闲零开销"。第一次使用后常驻一份接入进程是可接受的，只要它是常数级（见 G3）。
- 不解决"多个 agent 操作同一个 tab"的所有权问题。规则层面要求 agent 只操作自己创建的页面，接入层不强制仲裁。
- 不隔离共享 profile 内的 cookie、登录态、localStorage。这是共享 Chrome 的固有属性。
- 不为其他 OS 用户提供访问。接入层只服务当前 OS 用户。

## 4. 约束与不变量

- C1 Chrome 仍是全局唯一一份、持久 profile、GUI 有头、无 `--enable-automation`，由现有启动脚本负责，父进程为 launchd 而非任何 agent 会话。本文不改变这一层。
- C2 **不再要求接入层必须是 MCP**。用户已明确放开：只要 agent 在会话内能方便地调用浏览器，走 MCP 或走 shell CLI 都可以。
- C3 接入层的一切子进程**不得挂在 agent 会话进程之下**，否则会话退出会连带杀掉共享组件。
- C4 不新增监听 TCP 端口的服务。现有 CDP 端口（默认 9224）本身无鉴权，接入层不得再扩大暴露面（局域网可达、HTTP Origin/DNS rebinding 等）。
- C5 插件不得依赖机器上的偶然状态（某个 npx 缓存目录、Homebrew 全局包的恰好版本）。可执行文件的来源和版本必须由插件明确固定并在 doctor 中校验。
- C6 与 Codex CLI 兼容：接入方式在 Codex 下也应可用；至少不能比现状更差。
- C7 遵守仓库 skill 规则：SKILL.md 不超过 200 行，不引用 skill 目录外的路径，不硬编码用户名。

## 5. 功能需求

### 5.1 调用入口

- F1 插件提供**唯一入口**（一个脚本或命令），agent 通过它完成全部浏览器操作。SKILL.md 只展示这个入口，不出现可被复制的裸底层命令。
- F2 入口在每次调用时自动完成前置保障：Chrome 未运行则拉起；接入进程未运行或状态不符则拉起或修复；然后执行请求。用户和 agent 都不需要单独执行"启动"步骤。
- F3 入口只接受**白名单命令**，至少包括：列页面、新建页面、关闭页面、导航、截图、快照、执行脚本、点击、填表、处理弹窗、读 console。默认拒绝生命周期命令（start/stop/status 等由 doctor 或内部处理）、切换选中页面、扩展/内存/性能/仿真/网络类命令。
- F4 入口拒绝调用方覆盖接入层的关键参数（会话标识、浏览器地址、无头、隔离 profile、工具类别、文件系统根等）。
- F5 文件路径类参数（截图落盘、上传等）默认禁止或限定到当前工作目录；不允许相对路径，因为底层进程的 cwd 属于第一个启动者。
- F6 新建页面默认在后台打开，不抢用户前台焦点；只有明确需要用户旁观时才前台。
- F7 底层返回的工具级错误（如"页面有弹窗未处理"、"类别已禁用"）必须以非零退出码呈现，agent 不得因 exit 0 误判成功。
- F8 输出形态对 agent 友好：默认紧凑文本，支持结构化 JSON；截图作为文件路径返回时，SKILL 要说明如何读取和清理。

### 5.2 并发与隔离

- F9 所有页面级操作**必须显式带页面标识**，不得依赖"当前选中页面"这一全局状态。入口对缺失页面标识的页面级命令直接拒绝。
- F10 页面标识、快照元素 uid 与产生它的页面绑定；一个 agent 的快照不使另一个 agent 的 uid 失效。（1.9.0 已满足，见第 8 节实测，需在验收中保留。）
- F11 页面级弹窗、console、network 数据按页面隔离，一个页面的弹窗不阻塞其他页面的操作。（1.9.0 已满足。）
- F12 **页面标识跨接入进程重启不得复用**。接入进程重启后，旧标识必须被拒绝而不是静默映射到另一个（可能是用户自己的）标签页。这是 P0：实测中一个测试页原为 8 号，重启后 8 号变成了用户的 Bing 标签页。
- F13 长操作有上界：SKILL 规定单条命令控制在 30 秒内，长等待拆成短轮询；接入层的排队超时行为要可预测，一个 agent 的慢调用不得让其他 agent 的调用静默失败。

### 5.3 生命周期与恢复

- F14 接入进程按需拉起，父进程为 launchd（detached），不随任何会话退出而死。
- F15 两个 agent 同时发现接入进程不在并同时拉起时，必须只产生一份实例，不出现双实例、互删 socket/pid、孤儿子进程。需要每端口一把原子启动锁。
- F16 接入进程的**任一组件**崩溃（守护层或实际执行层）都必须能被下一次调用检测到并重建。"守护层还活着但执行层已死"的假健康状态不可接受。
- F17 崩溃或重建后不自动重放有副作用的命令（点击、填表、导航），由 agent 收到明确错误后自行决定。
- F18 Chrome 重启而接入进程未重启时，旧页面标识应返回"页面不存在"而非指向新页面。
- F19 接入进程长期运行的内存应有上界；关闭的页面对应的监听器、collector、快照应可回收。是否实现空闲自动退出（idle TTL）为开放问题（见第 9 节）。

### 5.4 诊断

- F20 doctor 至少检查：底层可执行文件精确版本、接入进程是否运行及其完整启动参数是否符合安全指纹、执行层健康（能完成一次只读调用）、socket 属主与权限、是否存在多余或未知实例、是否存在被误启动的无头 Chrome。doctor 只报告，不自动杀不确定的进程。

## 6. 非功能需求

- N1 内存：未使用浏览器的会话 0 额外进程；全机首次使用后常驻不超过约 250 MB（一份守护 + 一份执行层）；不随会话数增长。
- N2 延迟：单次短命令端到端不超过 1.5 秒（含入口脚本的前置检查）；排队时的额外等待等于前面命令的实际耗时，不叠加固定开销。
- N3 安全：不新增 TCP 监听；本机跨用户通信通道（如 unix socket）应放在当前用户 0700 目录下、属主与权限受校验、拒绝 symlink 抢占。同 UID 进程可访问是可接受的，因为它们本来就能访问 CDP 端口。
- N4 隐私：接入层不得把工具参数（填表内容、脚本、页面 URL 和标题）写入长期日志；截图临时文件目录权限受限。
- N5 可移植：不硬编码用户名与机器特定路径；macOS Bash 3.2 与 shellcheck 通过。

## 7. 设计方向（供实现方参考，非规定）

评估过的三条路线：

| 路线 | 描述 | 结论 |
|---|---|---|
| A 现状 | 每会话一份 stdio MCP | 不满足 G2、G3 |
| B HTTP 桥 | stdio 转 Streamable HTTP，宿主用 discovery cache 懒连接 | 懒连接链路实测成立，但需 fork 第三方桥（绑 loopback、鉴权、404、日志）、新增 TCP 端口、桥须 launchd 常驻。违反 C4，复杂度高。放弃。 |
| C CLI daemon | 用 chrome-devtools-mcp 自带的 `chrome-devtools` CLI：一份 detached 守护进程 + 一份执行层，agent 每次调用是一个短命 CLI 进程，经 per-user unix socket 通信 | 满足 G1 到 G3、C2 到 C4；并发隔离实测成立；原样使用有 6 个阻断项。**推荐方向**，最终形态为"受控入口 + 精确版本 + 启动锁 + 执行层监管 + 页面标识不跨重启复用"。 |

C 路线里两项无法只靠入口脚本解决，需二选一，倾向前者：

1. 给 chrome-devtools-mcp 打小补丁：执行层退出时守护层同步退出（解 F16）；页面计数器带纪元或持久化不复用（解 F12）。
2. 入口脚本自行维护守护进程纪元号，随每个页面标识一起返回给 agent，校验不通过即拒绝。

## 8. 已确认的事实（2026-09-09 实测，chrome-devtools-mcp 1.9.0）

供实现方直接使用，避免重复验证：

- 宿主对 stdio MCP 每会话一份、不重连；对 HTTP MCP 支持 `MCP_DISCOVERY_CACHE=1` 懒连接（首次工具调用才连）。
- `pageIdRouting` 默认开启，页面级工具强制要求 pageId；但 `selectedPage` 全局状态仍存在，`new_page` 会改写它，`select_page` 和扩展触发类工具仍依赖它。
- 快照 uid 按页面存储；弹窗、console、network collector 按页面隔离；network 类别关闭后 collector 仍在收集（每页最多约 3000 条请求对象）。
- 所有工具调用经一把全局互斥锁串行；CLI 客户端与守护层到执行层都是 60 秒超时。实测 A 的 3 秒调用使 B 的瞬时调用等待 3.4 秒。
- CLI 命令表没有 `wait_for`；`evaluate_script` 语法为 `evaluate_script '<函数>' --pageId <id>`，其余页面级命令 pageId 是第一个位置参数。
- CLI 在守护进程不存在时会用**当前命令的参数**自动起一个；不带浏览器地址时会自己开无头隔离 Chrome。这是 F1、F4 的直接动因。
- 守护进程 socket 位于 `/tmp`，路径含 uid，权限 `srwxr-xr-x`；macOS 上 connect 需要写权限，其他用户默认连不上，但路径可预测、可被预占造成 DoS。
- 执行层被杀后守护层仍报告 running，后续调用返回 `Not connected`，不自愈。
- 守护进程重启后页面编号从 1 重新开始。
- CLI 模式默认把 `allowUnrestrictedPaths` 置真、默认开启 extensions 与 memory 类别；启动参数须显式关闭。
- 5 轮双客户端同时冷启动未复现竞态，但源码无锁，竞态存在。
- 本机 Homebrew 全局 `chrome-devtools` 为 0.21.0，1.9.0 仅存在于 npx 缓存。C5 的直接动因。

## 9. 开放问题（待用户拍板）

1. **接入层空闲是否自动退出**：常驻约 200 MB 是否可接受？若要 idle TTL，需改守护进程，并保证退出后下次调用透明恢复。
2. **F12/F16 的解法**：打补丁上游 vs 入口脚本记纪元号。
3. **Codex 侧的入口形态**：同一个脚本经 Bash 调用即可，还是需要 Codex 插件层的额外注册？
4. **权限规则**：Claude Code 侧建议只 allow 入口脚本、deny 裸 `chrome-devtools`；规则写入用户级还是项目级配置，由安装步骤生成还是文档指引？
5. 与正在进行的 chrome 插件重构如何合并：本文的入口脚本、doctor、SKILL 改写应在重构分支落地还是重构合并后另起分支。

## 10. 验收标准

- [ ] 20 个以上并存会话、无一调用浏览器时，`ps` 中不存在任何接入层进程。
- [ ] 3 个会话交错执行新建页、快照、点击、填表、执行脚本、截图各 100 轮，DOM、console、uid 无跨页串扰。
- [ ] 100 轮以上双/三客户端同时冷启动，每轮恰好 1 份守护 + 1 份执行层 + 1 socket，无孤儿。
- [ ] 分别杀死执行层、杀死守护层（空闲与执行中两种）：当前调用得到非零明确错误，下一次调用无需人工干预恢复，且只连配置的 Chrome，不产生无头 Chrome。
- [ ] 守护进程重启后，旧页面标识被确定拒绝，绝不落到任何现有标签页（在隔离测试 Chrome 上验证）。
- [ ] 版本错误、浏览器地址错误、缺安全参数、stale pid、迟就绪启动均有确定的修复或 fail-closed 行为。
- [ ] 入口拒绝：生命周期命令、切换选中页、调用方传入会话标识与浏览器参数、相对或越界文件路径、扩展/内存/PWA 类命令。
- [ ] 工具级错误与传输错误都以非零退出码返回，输出可被 agent 判定。
- [ ] 24 小时以上、多标签页、console 高频输出的 soak 测试，常驻内存有上界。
- [ ] SKILL.md 不超过 200 行，示例全部使用唯一入口，含正确的 evaluate 语法、无 `wait_for`、页面所有权与重启后标识作废的规则。
- [ ] doctor 能发现多余实例与误启动的无头 Chrome，且不误杀用户进程。
