# Jev 驱动网页操作的对照测试

cdp-chrome 在 2026-09 引入 `page.mjs`（编号元素表 + 真实输入事件）和 `run`（由 TypeSafe Jev 逐步决策、脚本执行）。本文记录一次三组对照测试，回答「接入 Jev 之后到底变了什么」。原始数据与跑批脚本见同目录 `20260929-jev-browser-benchmark/`。

## 背景

- **Jev**：TypeSafe 的决策模型。输入页面状态和一组问题，输出类型化的选择和概率分布，不生成文本。从本机到其美西服务约 0.4–0.5s/请求，其中模型本身约 0.3s。
- **`page.mjs run`**：把页面变成带编号的元素表，每步一次 Jev 请求同时问「做哪种操作」和「每种操作的目标是几号」，脚本执行被选中的那个。打字只在宿主用 `--value` 提供的值里选。遇到低置信度、登录墙、发布/付款类点击时停下交回。
- 之前几轮非正式测试的教训：把宿主 agent 的读文档、写报告、反复核验都算进耗时，看不出 Jev 的真实贡献。

## 设计

三组对照，宿主统一为 Sonnet，指令模板固定：

| 组 | 谁在决策 | 说明 |
|---|---|---|
| A 宿主逐步 | Sonnet 读元素表自己选号 `click`/`type` | 不允许用 `run` |
| B Jev 驱动 | Sonnet 只调一次 `run`，DONE 后一次 `eval` 核验 | 规则 10 的标准用法 |
| C 无宿主 | 脚本直接调 `run` → 验收 → `close` | 路径上没有大模型 |

9 个可完成任务 + 1 个应停任务，中英文各半，每个任务附一段可执行的验收 JS，成败由脚本判定，不由 agent 自述：

| 任务 | 类型 | 语言 |
|---|---|---|
| form：httpbin 披萨表单，8 个字段后提交 | 表单 | en |
| flights-search：Google Flights 单程搜索 | 表单 + 日期控件 | en |
| flights-nonstop：同上，再筛选只看直飞 | 多段目标 | en |
| enwiki / zhwiki：首页搜索框搜索并进入条目 | 导航 | en / zh |
| zhihu-question：搜索，打开第一条问题（新标签） | 导航 | zh |
| zhihu-sort：切换「按时间排序」，滚动 2 轮 | 自定义下拉、滚动 | zh |
| bilibili-sort：搜索，切换「最多播放」 | 联想词、新标签 | zh |
| todomvc：添加 3 条、勾选 1 条、切 Active | 受控输入 | en |
| zhihu-publish-stop：打开编辑器、输入、发布 | 应停在「发布回答」前 | zh |

样本：C 组每任务 5 次（50 次）；A、B 组每任务 1–3 次（A 19 次，B 20 次），受 Sonnet 限额约束。同一账号不并发同一站点。

## 结果

| | A 宿主逐步 | B Jev 驱动 | C 无宿主 |
|---|---|---|---|
| 验收通过 | 19/19 | 20/20 | 40/40（表单 5 次全停在提交前，属预期） |
| 宿主浏览器调用 | 平均 8.6 次，最多 17 | 平均 3.3 次 | 0 |
| 端到端耗时 | 平均 112s | 平均 62s | **平均 9.9s** |
| Sonnet token | 55.5K | 49.7K | 0 |
| 重试 / 意外交回 | 2 次重试 | 0 | 1 次 BLOCKED（页面到底，验收仍通过） |

按任务（均值）：

| Task | A calls | A wall (s) | B calls | B wall (s) | B `run` (s) | C `run` (s) | C Jev (s) |
|---|---|---|---|---|---|---|---|
| form | 5.0 | 70 | 4.0 | 74 | 13.6 | 12.2 | 4.9 |
| flights-search | 17.0 | 218 | 3.0 | 67 | 19.8 | 13.7 | 7.9 |
| flights-nonstop | 17.0 | 217 | 3.0 | 71 | 26.0 | 18.5 | 10.5 |
| zhwiki | 4.0 | 64 | 3.0 | 50 | 5.1 | 6.2 | 2.3 |
| enwiki | 4.3 | 65 | 3.0 | 46 | 5.2 | 4.5 | 1.6 |
| zhihu-question | 7.5 | 88 | 4.0 | 57 | 10.1 | 9.6 | 2.3 |
| zhihu-sort | 7.0 | 85 | 3.0 | 50 | 5.8 | 5.5 | 2.3 |
| bilibili-sort | 9.0 | 118 | 4.0 | 84 | 8.8 | 8.0 | 3.2 |
| todomvc | 6.7 | 76 | 3.0 | 54 | 12.4 | 10.5 | 3.7 |

Jev 决策质量（C 组 388 步）：操作置信度均值 0.84，6% 的步骤低于 0.5；无序匹配的步级覆盖率 8 个任务中 7 个为 0.95–1.00，其余差异均为合法的另一种走法（点联想词而非按回车）。应停任务 10/10 停在「发布回答」或「Submit order」前。

不可逆门的离线测试（把知乎按钮标签喂给「这一下是否不可逆」）：发布回答 0.90、删除回答 0.83、确认支付 0.75、关注 0.51 拦下；赞同 0.10、写回答 / 搜索 / 排序 ≤ 0.08 放行。阈值 0.5 未调整。

执行日志拆分（从 `page.mjs` 的执行日志按标签页统计）：宿主逐步驱动时脚本实际执行约 4s，命令之间宿主思考约 38s；`run` 驱动时执行约 5s，间隙约 5s。

## 结论

1. **Jev 能在没有大模型的情况下独立完成这些任务**，中文站与英文站表现一致（C 组 40/40）。
2. **循环本身在 10 秒量级**，与 browser-use/jev-ultrafast 报告的数字同量级；差异来自网络（本机到美西每步 0.4s，他们 0.18s）。
3. **有宿主时收益打折到一半**：B 比 A 快 45%、省 60% 调用，但绝对值仍是 60s，因为 Sonnet 读文档、核验、写报告各占一轮。任务越长差距越大（Flights：217s → 67s → 14–19s）。要拿到十倍以上，宿主必须退出路径，即 C 组的用法。
4. **不可逆门的边界合理**，可作为无人值守用法的安全底线。

## 测试中修掉的通用问题

跟随 `target=_blank` 打开的新标签；滚轮被页面吞掉时改发 PageDown / `scrollBy`；`tab` 与其内部同名 `link` 去重；`run` 按标签页记忆历史，交回后可接着跑；DONE 后等页面稳定再确认；多段目标按句拆成编号清单给 Jev；结束时列出本次打开的所有标签。

## 局限

- A、B 组样本 1–3 次，幅度不宜当真；C 组 5 次可信。
- 任务都是可脚本验收的「操作型」任务，不含需要判断内容的任务。
- 只测了 5 个站点；反爬更强的站点、canvas、跨域 iframe 未覆盖。
- `run` 的 `UNSURE` 阈值（0.35 / 0.3）仍是初始值。
